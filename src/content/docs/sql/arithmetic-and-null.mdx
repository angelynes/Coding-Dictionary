## Integer division pitfall

<Entry term="2 / 10 = 0 ?!" short="Whole ÷ whole drops decimals">
<Fragment slot="code">

```sql run
SELECT 2 / 10        AS int_math,
       2.0 / 10      AS decimal_math,
       2 * 100.0 / 10 AS percent;
```

</Fragment>

- **Problem**: integer ÷ integer gives a **truncated integer**, so `2 / 10` is `0`.
- **Fix**: multiply by `1.0` or `100.0` to force floating-point maths, e.g. `count_dead * 100.0 / count_all` gives an accurate percentage.
- **Default names**: calculated columns without an alias get placeholder names like `?column?` (PostgreSQL). **Always use `AS`.**

</Entry>

## Missing data (NULL)

<Entry term="IS NULL · IS NOT NULL" short="Check for missing values">
<Fragment slot="code">

```sql run
-- returns nothing!
SELECT name FROM celebs WHERE twitter_handle = NULL;

-- correct
SELECT name FROM celebs WHERE twitter_handle IS NULL;
```

</Fragment>

<Concept>NULL</Concept> represents missing or unknown data. It **cannot** be checked with `= NULL` or `!= NULL`; those always return FALSE or NULL.

Check it with:
1. `WHERE column_name IS NULL`
2. `WHERE column_name IS NOT NULL`

</Entry>
